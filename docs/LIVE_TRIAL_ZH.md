# 原生 EXE 上车测试速查

本次使用 **AEIS-Engineer.exe**，不需要浏览器、Simulator Controller 或 Crew Chief。
仍是实验版，尚未通过真实麦克风、耳机、本人驾驶及 VR 负载的完整验收。
先在 Practice 中测试；进站与驾驶由你判断，程序不启动游戏、不驾驶、不改进站设置。

## 1. 停车准备：确认版本和语音

1. 正常关闭旧 AEIS，再打开新构建的 `dist/AEIS-Engineer.exe`。旧安装与快捷方式
   不会自动更新。新版启动先显示 **上车检查**；第一次解包可能需要几秒。
2. 点 **设置语音与试听**，分别勾选 **启用按住说话与后台 PTT**、**启用近车语音**，
   然后点 **应用语音设置**。这两个开关独立，光勾选还没有生效。
   首次设置默认关闭；旧版迁移保留已有 PTT 设置，新增的近车语音开关保持关闭。
3. 输入选你的桌面麦克风，输出选 VR 耳机；不选则按每次录播时的系统默认设备解析。
   指定设备失效不会换到其他设备。戴上耳机点 **试听（点击才播放）**，亲耳确认声音
   来自正确设备且音量合适。看见设备名或“已预备”不能代替试听。
4. 默认按住 **F9**，听到提示音后说“还有多少油”，说完松开。也可改 F8–F12 或绑定
   方向盘按钮，再应用。选不与游戏功能冲突的按钮；程序只监听，不发送游戏按键。
   先核对“最近识别”文字，再听回答。没进车时回答证据不足是正常的。
5. 在游戏前台、戴 VR 的状态再测试一次 PTT。不要边开车边打字或读长段文字。
   每次收音最长 12 秒；超时未松开会取消，不会自动发送截断的问题。

“上车检查”显示的是**已应用的设置和当前软件状态**，没有“全部通过”的灯。
真实听音、识别准确度和驾驶负载下的及时性仍须实际检查。

## 2. 先确认录制，保留一次测试的完整证据

在 **模型与本地设置** 确认 **将原始遥测及近车诊断日志记录到本机**。
新设置默认录制，但已经保存的关闭偏好不会被覆盖。进入驾驶后核对原始录制和
诊断日志两条状态都在记录；显示错误、上限或“本连接未录制”时先停车处理。

- 原始数据：`%LOCALAPPDATA%\iRacingAIEngineer\captures`，每次运行总预算 4 GiB。
- 事件与软件播放诊断：`%LOCALAPPDATA%\iRacingAIEngineer\trials`，每次运行 1 GiB。
- 达到上限不会自动删除旧数据，也不保证录完整场耐力赛。
- 全部留在本机；不要把原始遥测、日志、配置或密钥上传到公开 GitHub。

## 3. 本人进车后验证三个闭环

| 要验证的功能 | 操作及预期 | 不能算通过的情形 |
|---|---|---|
| 近车 Spotter | 离开维修区后检查近车数据和音频状态；自然遇到并排车时核对左右占位与后续清空提示 | 单纯启动问候、周围没有车、只有“数据就绪”，都不是近车播报验证 |
| 燃油问答 | 问“还有多少油”并与游戏当前油量比较；首次过线后完成默认至少 5 个有效完整圈，再问“还能跑几圈” | 学习未完成时不应捏造续航；Practice 无至终点预算是正常的 |
| 弯道建议 | 积累完整、干净、可比圈后问“哪里可以改进”或“哪里丢时间” | 没有最新圈中的重复证据时应等待；不保证跑固定圈数就一定产生建议 |

进出站、加油、出界、事故、不完整圈及不可靠数据会影响有效圈筛选。
观战朋友、回放和车库状态不能代替本人驾驶。不要降低门槛换取数字。
弯道建议是观测损失和练习假设，不保证提速；不会凭空要求多吃路肩。

近车音频**不等燃油学习或 DeepSeek**。初始左右清空时保持安静是正常的；
前后车纵向距离问答也不是左右近车 Spotter。若没有自然发生并排场景，记为“未测”，
不要刻意制造并排、事故、断线或其他危险测试条件。

## 4. 没有声音时，按环节排查

1. **开关**：上车检查是否仍显示近车语音或按住说话已关闭？勾选后需要应用。
2. **数据**：是否等待本人上车/离开维修区、过期或字段不可用？若明确显示 SDK 近车
   字段关闭/不可用，当前无法判定，不是赛道清空；保留这条诊断，不改模型提示词。
3. **输出**：是否准备中、暂停、音量零或输出故障？停车后检查输出选择，刷新设备、
   应用并试听。软件“已调用播放”不代表你真的听到。
4. **PTT**：没有收音状态，先查开关/按键；有状态但没识别文字，查麦克风/识别；
   文字正确但没有声音，查回答和输出。不要把每种问题都归咎于 API。

常用燃油、交通、驾驶短句使用本地直答。DeepSeek 是可选解释层；保存密钥、开启云端
和真实 API 请求成功是三件事，不能相互替代。测试这些本地闭环无需开启云端。
需要复杂进站比较时，再按 [原生使用说明](WINDOWS_DESKTOP.md) 设置已确认的参数；
不要为了出现策略数字随意填油箱、进出站点、损失时间或轮胎校准。

## 5. 停车收尾与复盘

自然结束驾驶后，旧燃油/驾驶建议应撤回。停车后停止录制并等待收尾，或正常关闭
应用等待退出；保持游戏连接直到记录收尾，不要直接杀进程。重新打开后可在
**采集复盘** 加载已结束的记录，在设置页使用 **回放近车诊断日志…** 检查
“判定→尝试→软件播放开始/完成”链路。
回放一致不证明当时听到了声音，也不能伪装成新一次实时验收。

跑完请保留：大约测试时段、车/赛道、三个闭环分别成功/失败/未测、听到或漏掉提示的
大约时刻、PTT 识别是否正确，以及 VR 是否明显卡顿。私有日志留在本机供复查。
细节见 [私有回放说明](PRIVATE_TRIAL_REPLAY.md) 与 [试用构建边界](NATIVE_TRIAL_BUILD.md)。

旧网页面板另见 [legacy browser guide](LIVE_APP.md)。它的 Practice-only/英文/隐藏页静音
限制不适用于这份原生 PTT 测试流程；关闭原生窗口会收尾并退出，不是关闭一个网页标签。
